# ADR-001 分享持久保留策略——活链接默认永久，过期一律 opt-in

- 状态：已采纳　日期：2026-10-04

## 背景

持久化纪律要求车道 1 的 append 型 kind 必须带保留策略（docs/PERSISTENCE_LANES.md
「车道 1 MUST」），历史债务清单曾把 `shares` 列为「长期堆积、无保留」。但分享是
用户**主动创建且对外分发**的活链接：短链可能已贴进 issue / 群聊 / 文档，
服务端悄悄删除等于弄断别人的链接——这与通知/任务类「不清理只是占空间」的
自动数据性质不同，不能套同一条保留规则。该域经三轮演进：A2 评审定基调、
P-20261002-71 引入 snippet 24h、P-20261003-29 补 file 形态 opt-in TTL。

## 决策

**分享记录（kind `shares`）默认永久保留，服务端不做任何自动过期清理；
一切过期都是显式 opt-in。**分形态：

- **file/目录分享**：默认永久（A2 决策原样保留）。用户可通过创建后的结果卡
  或 `SetExpiry` 显式设有效期，零值恢复永久；
- **snippet 分享**：创建即定 24h（`store.SnippetTTL`），**不可调整**（`SetExpiry`
  对 snippet 拒绝）——文本片段临时性强、暴露面应短，短命是安全边界而非缺陷；
- **统一语义**：倒计时是安全边界，幂等重建（重复分享同一目标）**不刷新**
  `CreatedAt`/`ExpiresAt`，防「重复分享一次=暗中续期成永久」；到期清理走单一
  管线 `CleanupExpired`（模块 ticker + 访客面 410 判定双保险，访客首踩惰性删除）。

## 后果

- 正面：活链接不会悄悄断；泄露有两条独立收口手段——`Rotate` 代际轮换（立即作废
  旧链）与 opt-in TTL（限时暴露）；token 确定性派生的「同内容恒同短链」语义完整。
- 接受的负面：`shares` 无上限增长（由用户驱动、量级为个位到十位数，可忽略）。
- 重新评估触发点：若未来出现合规类「到期必须物理删除」需求，做成**创建时默认
  不选的 opt-in 档位扩展**，不改变「默认永久」基调。
