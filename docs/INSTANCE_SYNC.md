# 多实例管理与同步（INSTANCE SYNC）

> 面向使用者的子系统说明：一个 Codecombo 实例如何管理多个其他实例、在实例间
> 同步项目与上下文、以及换机时如何整体迁移。实现落点 `server/api/sync/`、
> `server/proxy/`、`server/store/`（instance / syncledger / credsync）。

## 1. 多实例管理

- **实例注册表**：本机实例可登记多个远程 Codecombo 实例（URL + 访问 Token +
  可选配对密钥），全部加密落盘。注册表同时是「接管/同步」的对端寻址面。
- **集中代理**：所有对远端实例的操作（面板、终端、文件、审批）经本机实例的
  代理通道转发（`/api/proxy/*`、`/ws/proxy/:instanceId/*path`），对端实例只需
  正常开启远程访问，无需额外端口。连接池 + 并发控制见 `server/proxy/`。
- **健康总览与值班大屏**：实例清单页与值班大屏均聚合各实例健康摘要
  （`GET /api/system/health` 语义对齐），一键直达对端面板或终端。
- **能力探测**：对端能力经 `GET /api/meta` 的 capabilities 声明（同步能力为
  `sync` 项）——对端版本较旧未声明时相关功能显示「需升级」并降级，不做盲调用。

## 2. 实例间项目与上下文同步

把「项目本体（目录树，含/不含 `.git` 两档）+ 上下文包（会话 transcripts、
策展、项目笔记、项目域定时任务）+ 全局单元（全局片段、自定义运行时注册、
审批规则表、接续链定义、界面状态）」在实例间整体搬运——新实例从零到与源
实例体验一致，一次同步完成。

- **同步单元与指纹**：跨实例稳定键 `project:<根目录基名>` / `<kind>:<基名>`；
  聚合指纹 = 规范化相对路径 + size 排序后的 sha256（不取 mtime，跨平台稳定）。
  git 仓库的枚举感知 `.gitignore`，非 git 目录按默认排除清单（node_modules、
  target、dist 等）处理；条目数触顶时如实回告截断。
- **同步账本四态判定**：每「单元 × 对端」记录上次成功同步时两端指纹，计划
  阶段以基线为参照给出建议——
  | 两端状态 | 判定 | 默认动作 |
  |---|---|---|
  | 两端均未变 | skip | 不动 |
  | 本端变、对端未变 | local-newer | 建议 push |
  | 对端变、本端未变 | peer-newer | 建议 pull |
  | 两端都变 | conflict | 默认不勾选（git 仓库建议走 git 自己的远端协作） |
- **执行与落位安全**：pull/push 后台执行、单任务互斥；对端落位先 staging 后
  原子换名，已存在文件逐文件覆盖且被覆盖文件先移入 `.sync-backup/`（保留
  3 份）；落位后自动注册项目；plan 预览与落地两道磁盘水位预检。
- **定时同步**：按「方向 + 项目集 + 上下文集 + 目标集 + 冲突策略」配置定时
  任务；冲突策略三档——safe（只做安全项，冲突留通知裁决）/ local-mirror /
  peer-mirror（镜像档 = 显式单向权威，适合备份场景）。
- **密钥红线**：定时/自动同步的载荷**构造性排除**一切密钥（凭据库、锁密码、
  实例 Token、SSH 主机凭据、分享 token），并有测试红线断言密钥字节不出现在
  任何载荷中。需要迁移凭据走下一节的携密通道。

入口：活动栏「同步中心」面板 / 命令面板 / 文件树右键「同步到其他实例…」
（单项目轻投递）。

## 3. 手动携密同步（在线换机路径）

定时红线之上唯一的人工携密通道，设计目标是「换机不重配」：

- **纯人工纪律**：携密开关只能由人手动勾选（服务端硬拒定时/自动化源触发）。
- **配对密钥端到端加密**：两端各生成 32 字节配对密钥、与实例 Token 同屏人工
  抄录交换；传输时经 HKDF 派生会话钥 + AES-256-GCM 信封（附加数据绑定方向与
  序号，防重放/防中间人）；首次携密强制两端核对证书指纹短码后才会落盘。
- **落位恒 merge**：凭据档（git 凭据 + SSH 主机含私钥 + 部署凭据 + Agent
  Token）以 merge 语义并入目标机，走目标机自身的加密落盘链；实例 Token 与
  锁密码永不携带，仅哈希存储的令牌在新机重签。

## 4. 换机迁移——配置包导出/导入

与同步引擎同源的一次性整机迁移工具（设置 → 迁移）：

- **双模 `.scpkg` 包**：
  - `light`——四块配置（凭据 / 可携设置 / 实例注册表 / Agent Token），KB~MB 级；
  - `full`——四块配置 + 项目与上下文内容（分块加密信封，内存占用不随包体积增长）。
  整包用单一口令加密（建议 ≥8 位）；错口令与文件损坏返回同一文案，不泄露区别。
- **可迁 / 不可迁边界**（导出预览明示）：
  - 可迁：git 凭据、SSH 主机（含私钥）、部署凭据、Agent Token、白名单内系统
    设置（锁开关/TTL、通知偏好等；端口/绑定地址等机器拓扑字段构造性排除）；
  - 不可迁：锁密码哈希（新机重新首设）、仅哈希存储的机器 API/快速投递令牌
    （新机重签）。
- **三段式导入**：preview（解密预览，逐块计数 + 设置逐字段 diff + 项目清单，
  绝不显示秘密明文）→ apply（按块选择 merge / overwrite / skip 策略；任一块
  失败整体回滚）→ 结果报告（引导闭环：对端实例一键接入、锁密码首设提示）。

## 5. 与其他子系统的关系

- 换机迁移与同步共用打包/落位引擎（单元布局与 zip 载荷同构），区别在
  「持续双向 vs 一次性单包」与「默认不携密 vs 显式携密」。
- 远程部署（`server/deploy/`）负责把新实例二进制装上远程主机——典型链路是
  先部署出新实例，再用本文的同步/迁移把工作面搬过去。
- 审计：同步与迁移动作均入审计日志（只记单元数/字节数/计数等元数据，不记
  内容与秘密）。
